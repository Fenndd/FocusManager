# Спецификация: правила ведения

Спецификация — источник истины о **поведении** FocusManager. Код, который ей противоречит, — баг
(или спецификация устарела — тогда её нужно исправить в рамках задачи).

## Структура

- Один файл — одна функциональная область (`study-mode.md`, `apps.md`, …). Эти файлы
  **платформенно-независимы**: описывают, что видит и получает пользователь.
- `platforms/<platform>.md` — как требования реализуются на конкретной платформе,
  платформенные ограничения и платформенные требования.

## Формат требования

```markdown
### APP-003 Разрешение по имени файла
Если у события запуска известен только путь с другим каталогом, приложение разрешается,
когда имя исполняемого файла совпадает с именем файла из белого списка.

Платформы: Windows — done · Android — n/a
Примечание: ... (необязательно)
```

- **ID**: `<ПРЕФИКС>-<NNN>`. Префиксы: `SM` (режим учёбы), `APP`, `FLD`, `SITE`, `NTF`, `WIN`, `AND`.
  ID никогда не переиспользуются и не меняются.
- **Статусы платформ**: `done` — реализовано; `partial` — реализовано частично (пояснить в примечании);
  `planned` — должно быть, но ещё нет; `n/a` — на платформе неприменимо.
- Формулировки — проверяемые: из требования должно быть понятно, какой тест его подтверждает.
- Открытые вопросы помечаем `> ❓ Вопрос:` прямо под требованием — это сигнал владельцу продукта.

## Статус документа

Раздел спецификации по Windows восстановлен из существующего кода (состояние на 2026-09-30).
Места, где текущее поведение выглядит спорным, помечены как вопросы — их нужно подтвердить или
превратить в задачи на изменение.
