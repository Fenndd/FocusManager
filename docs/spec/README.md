# Спецификация: правила ведения

Спецификация — источник истины о **поведении** FocusManager. Код, который ей противоречит, — баг
(или спецификация устарела — тогда её нужно исправить в рамках задачи).

## Структура

- Один файл — одна функциональная область (`study-mode.md`, `apps.md`, …). Эти файлы
  **платформенно-независимы**: описывают, что видит и получает пользователь.
- `platforms/<platform>.md` — как требования реализуются на конкретной платформе,
  платформенные ограничения и платформенные требования.

## Платформы

Основные платформы: **Android, Windows, Linux** — функционал на них одинаковый (решение B5).
iOS — после финализации основных платформ, с тем подмножеством функций, которое позволяет iOS.
macOS не планируется.

## Формат требования

```markdown
### APP-003 Разрешение по имени файла
Если у события запуска известен только путь с другим каталогом, приложение разрешается,
когда имя исполняемого файла совпадает с именем файла из белого списка.

Платформы: Android — n/a · Windows — done · Linux — planned · iOS — deferred
Примечание: ... (необязательно)
```

- **ID**: `<ПРЕФИКС>-<NNN>`. ID никогда не переиспользуются и не меняются.

  | Префикс | Область | Файл |
  |---------|---------|------|
  | `GEN` | Общие требования к продукту | `product.md` |
  | `PRF` | Профили и режимы | `profiles.md` |
  | `TRG` | Способы запуска блокировки | `triggers.md` |
  | `SM` | Сессии | `study-mode.md` |
  | `APP` | Приложения | `apps.md` |
  | `SITE` | Сайты | `sites.md` |
  | `FLD` | Папки (ПК) | `folders.md` |
  | `CNT` | Контент: ключевые слова, разделы приложений, уведомления | `content.md` |
  | `NTF` | Уведомления FocusManager | `notifications.md` |
  | `STAT` | Статистика для пользователя | `stats.md` |
  | `SYNC` | Аккаунт и синхронизация | `sync.md` |
  | `TEL` | Техническая аналитика и приватность | `telemetry.md` |
  | `PAY` | Монетизация | `monetization.md` |
  | `WIN`, `LNX`, `AND`, `IOS` | Платформенные требования | `platforms/*.md` |

- **Статусы платформ**: `done` — реализовано; `partial` — реализовано частично (пояснить в примечании);
  `planned` — должно быть, но ещё нет; `research` — нужно, но реализуемость не подтверждена;
  `deferred` — платформа отложена (iOS); `n/a` — на платформе неприменимо.
- Формулировки — проверяемые: из требования должно быть понятно, какой тест его подтверждает.
- Открытые вопросы помечаем `> ❓ Вопрос:` прямо под требованием — это сигнал владельцу продукта.
  Вопросы уровня продукта собраны в [decisions.md](decisions.md); требования ссылаются на них по коду (`решение E7`).

## Статус документа

- Требования с `Windows — done` восстановлены из существующего кода (2026-09-30).
- 2026-10-02 спецификация переработана по решениям владельца (блоки A–E в `decisions.md`).
  Решения по защите от обхода, монетизации и релизу (блоки F–H) ещё не приняты — соответствующие
  требования помечены вопросами.
