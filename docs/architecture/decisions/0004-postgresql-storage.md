# ADR-0004: PostgreSQL вместо SQLite

- Статус: Принято
- Дата: 2026-09-30

## Контекст

Настройки и белые списки хранились в локальном файле SQLite (`%LOCALAPPDATA%\FocusManager\focusmanager.db`).
Решение владельца продукта: перейти на PostgreSQL. Приложение изначально создавалось под Windows.

## Решение

- Проект `FocusManager.Persistence.Sqlite` заменён на `src/Shared/FocusManager.Persistence.Postgres`
  (драйвер Npgsql), класс `PostgresWhitelistStore` реализует тот же `IWhitelistStore` — остальной код не менялся.
- Строка подключения: `ConnectionStrings:FocusManager` в конфигурации агента
  (`src/Windows/FocusManager.Agent/appsettings.json` или переменная окружения `ConnectionStrings__FocusManager`).
  Пароль в репозиторий не коммитится: переменная окружения, `PGPASSWORD` или файл `pgpass.conf`.
- Схема (таблицы `settings`, `allowed_apps`, `allowed_folders`, `allowed_sites`) создаётся хранилищем
  при первом обращении (`CREATE TABLE IF NOT EXISTS`, под advisory lock). Сама база и роль создаются заранее.
- Уникальность записей — без учёта регистра (уникальные индексы по `lower(...)`), как было в SQLite (`COLLATE NOCASE`).
- Тесты хранилища работают с настоящим PostgreSQL: строка подключения в `FOCUSMANAGER_TEST_POSTGRES`,
  каждый тест — в своей временной схеме. Без переменной тесты пропускаются (Skipped), а не падают.

## Альтернативы

- **Оставить SQLite.** Не требует сервера, но это противоречит решению владельца.
- **EF Core + миграции.** Для четырёх таблиц избыточно; при росте схемы стоит вернуться к вопросу
  (или взять лёгкий инструмент миграций, например DbUp).

## Последствия

- Для работы агента нужен доступный PostgreSQL. Если строка подключения не задана — агент не стартует
  с понятной ошибкой; если сервер недоступен — ошибка при старте/операциях (см. вопрос в `docs/spec/platforms/windows.md`, WIN-006).
- Данные из старой SQLite-базы автоматически не переносятся (задача `0010`).
- Разработчику и CI нужен PostgreSQL для тестов хранилища (задача `0006` — сервис PostgreSQL в CI).
- **Android:** прямое подключение телефона к PostgreSQL не рекомендуется (учётные данные внутри APK,
  открытый порт БД в сеть). Если Android должен использовать те же данные — нужен серверный API
  между приложением и БД; если данные на Android локальные — нужно локальное хранилище. Вопрос решается
  в задаче `0008`, до этого `FocusManager.Persistence.Postgres` используется только Windows-агентом.
