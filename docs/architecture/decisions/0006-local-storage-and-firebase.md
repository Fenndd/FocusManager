# ADR-0006: Локальное хранилище на устройстве + Firebase для облака

- Статус: Принято
- Дата: 2026-11-16
- Заменяет: ADR-0004

## Контекст

ADR-0004 перевёл хранилище Windows-агента на PostgreSQL. Это требует установленного сервера БД
на компьютере пользователя и противоречит требованию работать без интернета и без настройки (GEN-005).
Решения владельца: первая версия без облака (D1), облако — Firebase (D2), синхронизация и резервная
копия — только через аккаунт (D3, D5), на ПК — SQLite (C6).

## Решение

- **Локальное хранилище на каждом устройстве** — источник правил для блокировки, работает офлайн:
  - Windows и Linux — SQLite (`Microsoft.Data.Sqlite`), проект `FocusManager.Persistence.Sqlite`;
  - Android — Room (SQLite);
  - iOS (позже) — по платформе.
- **Firebase** — облако: аккаунт (Firebase Auth), синхронизация (Firestore), аналитика и отчёты о сбоях
  (Analytics, Crashlytics на Android; на ПК — через веб-SDK в Tauri-интерфейсе, ADR-0007).
- **Кто синхронизирует на ПК:** интерфейс (Tauri) работает с Firebase через официальный JS SDK и передаёт
  данные агенту по IPC; агент хранит их в SQLite и не ходит в облако сам.
- PostgreSQL удаляется из проекта (задача 0002).

## Альтернативы

- **Оставить PostgreSQL** — неприемлемо для обычного пользователя.
- **Supabase вместо Firebase** — PostgreSQL в облаке и клиент для C#, но бесплатные проекты засыпают;
  владелец выбрал Firebase.
- **Агент сам синхронизирует с Firebase через REST** — лишний код в агенте, а интерфейс и так постоянно
  запущен в трее. Можно вернуться, если понадобится синхронизация без запущенного интерфейса.

## Последствия

- Старая база SQLite пользователей Windows (`%LOCALAPPDATA%\FocusManager\focusmanager.db`) снова
  становится актуальной — переносить данные из PostgreSQL не нужно (задача 0010 отменена).
- Для тестов хранилища больше не нужен сервер PostgreSQL.
- Формат документов Firestore общий для всех платформ (задача 0021).
- Нужен проект Firebase, который создаёт владелец (задача 0023).
