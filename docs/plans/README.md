# Планы и задачи

- [`roadmap.md`](roadmap.md) — этапы (milestones) и порядок работ. Меняется редко.
- [`tasks/`](tasks/) — задачи. **Одна задача = один файл** `NNNN-kebab-case.md`, шаблон — [`tasks/_template.md`](tasks/_template.md).

## Поля задачи (YAML front matter)

| Поле | Значения | Смысл |
|------|----------|-------|
| `id` | `0001` | Совпадает с префиксом имени файла |
| `title` | строка | Кратко, в повелительном наклонении |
| `status` | `todo` · `in-progress` · `blocked` · `done` · `cancelled` | Текущее состояние |
| `type` | `feature` · `change` · `bug` · `refactor` · `research` · `chore` | `change` — изменение уже реализованного поведения |
| `platform` | `shared` · `windows` · `android` · `all` | Где меняется код |
| `milestone` | `M1`… | Этап из `roadmap.md` |
| `priority` | `high` · `medium` · `low` | |
| `depends_on` | `[0001, 0003]` | Задачи, которые должны быть `done` до начала |
| `spec` | `[APP-003, SITE-002]` | Требования спецификации, которых касается задача |
| `adr` | `[0002]` | Связанные ADR (если есть) |

## Жизненный цикл

```
todo ──► in-progress ──► done
  │           │
  │           └──► blocked (в разделе «Результат» — чего не хватает) ──► in-progress
  └──► cancelled (с причиной)
```

- Файлы задач **не перемещаются и не удаляются** — статус меняется только в front matter.
- Выполненная задача остаётся как история: что сделано и почему.

## Как агенту найти работу

```bash
grep -l "^status: todo" docs/plans/tasks/*.md          # все открытые
grep -l "^milestone: M1" docs/plans/tasks/*.md         # задачи этапа
```

Бери задачу с наивысшим приоритетом текущего этапа, у которой все `depends_on` — `done`.

## Правила для составления задачи

Задача должна быть выполнима агентом без уточнений:

1. **Контекст** — зачем, со ссылками на файлы/классы.
2. **Что сделать** — конкретные шаги.
3. **Критерии приёмки** — проверяемый список (тесты, команды, наблюдаемое поведение).
4. **Вне рамок** — что не делать, чтобы задача не расползлась.
5. Размер — один PR, который можно отревьюить за раз. Больше — разбей на несколько задач с `depends_on`.

## Нумерация

Следующий номер = максимальный существующий + 1. Если при слиянии двух веток номера совпали —
задача, влитая позже, получает следующий свободный номер (переименовать файл и поле `id`, поправить ссылки).
