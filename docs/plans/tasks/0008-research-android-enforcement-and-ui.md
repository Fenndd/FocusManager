## Контекст

Стек Android решён: Kotlin + Jetpack Compose, Room, Firebase (ADR-0005, ADR-0006).
`docs/spec/platforms/android.md` описывает механизмы как гипотезы — их нужно подтвердить прототипами
до основной разработки.

## Что сделать

1. Для каждой функции проверить механизм и ограничения на актуальных версиях Android (от API 26):
   - обнаружение запуска приложения (Accessibility, UsageStats), блокирующий экран;
   - фильтрация сайтов обоими способами (решение E4): адресная строка через Accessibility для
     поддерживаемых браузеров (Chrome, Samsung Internet, Opera, Firefox — SITE-005) и локальный VpnService
     с DNS-фильтром; обход через собственный зашифрованный DNS браузеров;
   - ключевые слова и разделы приложений (Shorts, Reels), скрытие уведомлений (CNT-*);
   - лимиты времени и запусков, геозоны и Wi-Fi (TRG-*);
   - права администратора устройства и закрытие экранов Настроек (PROT-007, PROT-008);
   - устойчивость к энергосбережению производителей (AND-007).
2. Изучить требования Google Play: использование Accessibility API, VpnService, фоновое местоположение,
   права администратора; что нужно для прохождения модерации.
3. Прототипы — вне `src/` (не коммитятся) или в отдельной ветке.
