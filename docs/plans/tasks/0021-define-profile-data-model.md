## Контекст

Сейчас модель — один набор белых списков (`WhitelistConfig`). Спецификация вводит профили с режимом
белого/чёрного списка, списками, триггерами и уровнем защиты (`profiles.md`, `triggers.md`,
`protection.md`), а данные синхронизируются через Firebase между Android, Windows и Linux (ADR-0006).
Формат документов должен быть общим для всех платформ (ADR-0005).

## Что сделать

1. JSON Schema документов в `contracts/`: профиль, списки (общие и платформенные — SYNC-005), триггеры,
   параметры защиты, записи статистики. Версия формата и правила совместимости.
2. Структура данных в Firestore (коллекции, документы пользователя) — описать в `docs/architecture/`.
3. C#-модели в `FocusManager.Core` и схема SQLite с версионированными миграциями; текущие белые списки
   переносятся в профиль «Учёба» в режиме белого списка.
4. Решить и записать в спецификацию правило совмещения нескольких активных профилей (вопрос в PRF-005)
   — предложить владельцу.

## Критерии приёмки

- [ ] Схемы в `contracts/`, описание Firestore, миграция SQLite с тестами.
- [ ] Существующие данные пользователя Windows переносятся без потерь.

## Вне рамок

- Экраны профилей и логика триггеров — задачи этапа M5 (создаются после этой).
- Подключение к Firebase — задача 0023.
