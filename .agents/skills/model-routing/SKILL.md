# Project Model Routing

Read the common sections and your client's section of the shared [orchestration policy](../../../docs/engineering/AI_ORCHESTRATION.md) before coordinating subagents. It owns the fixed model/effort tables, tier gates, brief, verification, and reporting rules. Executors read its common sections before work. Do not duplicate the policy in client profiles.

Identify coherent delegated results first; schedule independent assignments in parallel and dependent stages sequentially. Use the working default for substantive work unless a specific tier exception is justified. A sequential dependency does not make the orchestrator the implementer. When a stronger agent resolves its bounded question, return ordinary follow-up work to the working default. Keep short actions and coordination in the main session without agent quotas.

Apply the current client's supported launch settings from the policy; do not assume settings were executed merely because they were requested. Give bounded context and checks, inspect evidence proportionally to risk, and arrange independent verification when the orchestrator cannot assess a claim. The orchestrator retains responsibility and the user's confirmed decisions govern product behavior. This skill does not switch models automatically or enable tools.
